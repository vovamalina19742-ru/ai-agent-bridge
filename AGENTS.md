# РЕГЛАМЕНТ И АРХИТЕКТУРА ЛОКАЛЬНОГО АГЕНТА (AI_Agent)
## Модель ядра: `qwen2.5-coder:7b` (Ollama, Zero-Cost)

### 1. Архитектура и принципы
- **Автономный ReAct-цикл:** Оркестратор анализирует задачу, подбирает инструмент, запускает его локально и возвращает результат в контекст модели.
- **Динамический реестр (Auto-Discovery):** Каждый скрипт в `tools/` объявляет структуру `TOOL_SPEC`. Оркестратор автоматически формирует JSON-схему для Ollama без ручных правок.
- **Трехуровневая память и персистентность сессий (F15 + F16):** 
  1. Долговременная сессия (`session_store.py` $\to$ `session.json`): атомарное сохранение истории диалога при штатном выходе или `KeyboardInterrupt`, диалоговое восстановление при перезапуске с автоматическим триммингом под бюджет 32k.
  2. Фактологическая память (`memory.json` $\to$ `memory_manager.py`): сохранение постоянных фактов с гибридным (семантика + ключевые слова) поиском через `embedding_engine.py` (`nomic-embed-text`).
  3. Сохраненная база ссылок (`saved_links.json` $\to$ `web_fetcher.py` + `search_saved_links.py`): гибридный векторный поиск через RRF (Reciprocal Rank Fusion) и кэшированные эмбеддинги.

### 2. Подключенные инструменты (tools/)
1. **`consult_senior_ai.py` (Связь со Старшим ИИ / Antigravity):**
   * Консультация по сложным архитектурным вопросам, ревью кода, передача задач через Gemini Flash-Lite и мост `bridge_tasks.json`.
2. **`search_books.py` (Инженерная библиотека SQLite FTS5):**
   * Мгновенный полнотекстовый поиск (BM25, префиксы, `unicode61`) по базе `books_index.db` (362 книги PDF на `G:\Мой диск\книги`) с резервным фолбэком на прямое сканирование PDF.
3. **`book_indexer.py` (Индексатор книг SQLite FTS5):**
   * Инкрементальная индексация PDF с контролем `mtime`, нарезка на чанки 1200 символов с перекрытием 150 и сохранение в WAL-базу.
4. **`remote_server.py` (Управление Linux-узлом 192.168.1.100):**
   * Команды: `wake` (WOL пакет), `sleep` (S3 Suspend), `status` (пинг и SSH probe), `exec` (запуск bash-команд со строгим черным списком опасных команд).
5. **`network_scanner.py` (Сканер локальной сети):**
   * Многопоточный ping-sweep подсети `192.168.1.x` с извлечением MAC-адресов из ARP-таблицы (регулярное выражение с границами слов).
6. **`port_checker.py` (Сетевой зонд портов):**
   * Проверка доступности TCP-портов (80, 443, 22, 8080 и др.) на любом хосте.
7. **`web_fetcher.py` (Веб-клиент и экстрактор контента):**
   * Проверка HTTP-статуса со строгой проверкой SSL-сертификатов, извлечение чистого текста. Автоматически сохраняет метаданные страниц в `saved_links.json`.
8. **`search_saved_links.py` (Гибридный семантический поиск по ссылкам):**
   * Семантический поиск по смыслу + подстроки с RRF-ранжированием по сохраненным проектам в `saved_links.json`.
9. **`memory_manager.py` (Гибридная долговременная память):**
   * Сохранение и семантический recall (`nomic-embed-text`) ключевых фактов и архитектурных заметок в `memory.json`.



### 3. Правила разработки новых инструментов
- Код на чистом Python 3 с поддержкой UTF-8 (`sys.stdout.reconfigure(encoding="utf-8")`).
- Обязательное наличие словаря `TOOL_SPEC` с `name`, `description` и `parameters`.
- Обработка ошибок через `try-except` с таймаутами на сокетах и подпроцессах.
- Лаконичный вывод в консоль (только полезная информация без шума).

### 4. Жесткие правила обработки внешних ссылок (Anti-Hallucination)
- **Запрет подмены контекста:** При получении внешней ссылки (GitHub-репозиторий, документация, сторонний сайт) категорически запрещено подменять её содержимое списком локальных инструментов проекта из папки `tools/` или файла `memory.json`.
- **Обязательный вызов инструмента:** Модель обязана в первую очередь задействовать `web_fetcher` для физической загрузки данных по указанному URL.
- **Анализ только полученных данных:** Ответ должен строиться строго на основе текста, возвращенного инструментом `web_fetcher`. Если контент недоступен или пуст, агент должен прямо сообщить об этом или эскалировать задачу через `consult_senior_ai`, но не подменять внешний ресурс списком собственных файлов.
- **Поиск по ранее изученным материалам:** Если пользователь спрашивает «что мы смотрели про такой-то проект», просит найти ранее изученный репозиторий или ссылку — агент ОБЯЗАН в первую очередь использовать `search_saved_links`, а не пытаться вспомнить это из головы или заново качать из интернета.
